Activar · Explorar

Entrenamos nuestra IA con Teachable Machine

Vais a enseñar a una IA a reconocer 5 libros usando Teachable Machine, una herramienta gratuita de Google que no requiere saber programar.

Primero — entiende Teachable Machine

Mira este vídeo de 3 minutos antes de empezar:

Ver vídeo — Teachable Machine en español Abrir Teachable Machine
Guía completa — entrena tu clasificador de libros
  1. Elegid 5 libros de la biblioteca con portadas distintas y reconocibles.
  2. En Teachable Machine: "Nuevo proyecto" → "Proyecto de imagen".
  3. Cread 6 clases: una por cada libro (con su título) más una llamada "Ninguno".
  4. Para cada libro: fotografiadlo desde al menos 10 ángulos distintos — de frente, ladeado, con diferente luz, de cerca, de lejos. Mínimo 30 fotos por libro.
  5. Para "Ninguno": fotos de la mesa, la pared, la mano vacía.
  6. Clic en "Entrenar modelo" y esperad 1-2 minutos.
  7. Probad apuntando la cámara a cada libro. ¿Lo reconoce? Si alguno falla (menos del 80%), añadid más fotos y volved a entrenar.
  8. Cuando funcione bien: "Exportar modelo" → "Subir" → copiad la URL. Guardadla: la necesitaréis en el siguiente paso.
Reflexión del equipo — después de entrenar
  1. ¿Cuántas fotos habéis necesitado para que reconociera bien cada libro?
  2. ¿Con qué libro ha fallado más? ¿Por qué creéis que ha sido?
  3. ¿Qué pasaría si añadierais 200 libros más? ¿Seguiría funcionando igual?

🗄️
¿Para qué sirve TinyDB? — entiéndelo antes de usarlo

TinyDB es la memoria persistente de tu app.

Imagina un cajón con etiquetas. Tú metes algo en el cajón con una etiqueta (ej: "estado_El Quijote") y guardas el valor "Prestado a Ana García — 17/04/2026". Cuando cierras la app y la vuelves a abrir, ese cajón sigue ahí con ese valor dentro.

Sin TinyDB, cada vez que cerraras la app todos los libros volverían a "Disponible" porque la app no recordaría nada. TinyDB es lo que hace que el sistema de préstamo funcione de verdad.

⚠ Los datos se guardan solo en este dispositivo. Si usáis otra tablet, tendrá su propio TinyDB independiente.

04
Aplicar

Programamos los bloques en App Inventor

Id a la pestaña "Blocks" y construid estos bloques uno a uno. Son la lógica completa de la app.

Bloque 1 — Al arrancar la app
// Cuando se abre la app: activar la cámara
when Screen1.Initialize
  call ImageClassifier.StartContinuousClassification
Bloque 2 — Cuando la IA reconoce un libro
// La IA da un resultado continuamente
when ImageClassifier.GotClassification
  // Mostrar el libro reconocido
  set lblLibro.Text to result
  // Recuperar su estado actual desde TinyDB
  set lblEstado.Text to TinyDB.GetValue("estado_" + result, "Disponible")

La clave de TinyDB es "estado_" + el nombre del libro. Así cada libro tiene su propio cajón.

Bloque 3 — Botón REGISTRAR PRÉSTAMO

Guarda dos cosas en TinyDB: el estado actual del libro (para saber si está disponible) y una línea nueva en el historial acumulado (para no perder nunca el registro de quién lo tuvo).

when btnReservar.Click
  if lblLibro.Text ≠ "Apunta a un libro..."
    AND txtNombre.Text ≠ ""
    AND lblEstado.Text = "Disponible" then
    
    // 1. Fecha de hoy
    set local fechaHoy to Clock1.FormatDate(Clock1.Now, "dd/MM/yyyy")
    
    // 2. Guardar ESTADO actual (se sobreescribe cada vez)
    set local textoEstado to "Prestado a " + txtNombre.Text + " — " + fechaHoy
    TinyDB.StoreValue("estado_" + lblLibro.Text, textoEstado)
    
    // 3. Recuperar historial anterior y añadir nueva línea (nunca se borra)
    set local histAnterior to TinyDB.GetValue("historial_" + lblLibro.Text, "")
    set local lineaNueva to "PRÉSTAMO — " + txtNombre.Text + " — " + fechaHoy
    TinyDB.StoreValue("historial_" + lblLibro.Text, histAnterior + "\n" + lineaNueva)
    
    // 4. Actualizar pantalla
    set lblEstado.Text to textoEstado
    set txtNombre.Text to ""
    Notifier.ShowAlert("¡Préstamo registrado!")
  else if lblEstado.Text ≠ "Disponible" then
    Notifier.ShowAlert("Este libro ya está prestado")
  else
    Notifier.ShowAlert("Identifica un libro y escribe tu nombre")
  end if
Bloque 4 — Botón REGISTRAR DEVOLUCIÓN

Al devolver no se borra nada: el estado pasa a "Disponible" y se añade una línea nueva al historial con la fecha. El registro de quién tuvo el libro queda guardado para siempre.

when btnDevolver.Click
  if lblLibro.Text ≠ "Apunta a un libro..."
    AND lblEstado.Text ≠ "Disponible" then
    
    // 1. Fecha de hoy
    set local fechaHoy to Clock1.FormatDate(Clock1.Now, "dd/MM/yyyy")
    
    // 2. Cambiar el ESTADO a Disponible
    TinyDB.StoreValue("estado_" + lblLibro.Text, "Disponible")
    
    // 3. Añadir línea de devolución al historial (sin borrar nada)
    set local histAnterior to TinyDB.GetValue("historial_" + lblLibro.Text, "")
    set local lineaNueva to "DEVOLUCIÓN — " + fechaHoy
    TinyDB.StoreValue("historial_" + lblLibro.Text, histAnterior + "\n" + lineaNueva)
    
    // 4. Actualizar pantalla
    set lblEstado.Text to "Disponible"
    Notifier.ShowAlert("Libro devuelto correctamente")
  else
    Notifier.ShowAlert("Este libro ya está disponible o no hay libro reconocido")
  end if
Bloque 5 — Botón VER HISTORIAL

Añadid un botón btnHistorial con texto "VER HISTORIAL" en el Designer. Al pulsarlo muestra todos los movimientos del libro reconocido desde que se instaló la app.

when btnHistorial.Click
  if lblLibro.Text ≠ "Apunta a un libro..." then
    set local historial to
      TinyDB.GetValue("historial_" + lblLibro.Text, "Sin movimientos aún")
    Notifier.ShowAlert("Historial de " + lblLibro.Text + ":\n" + historial)
  else
    Notifier.ShowAlert("Primero apunta a un libro")
  end if

⭐ Ampliación — para quien termine antes
Segundo clasificador: reconocimiento facial en lugar de escribir el nombre

Si habéis terminado y funciona todo correctamente, podéis dar un paso más: en lugar de que el alumno escriba su nombre, que la cámara lo reconozca automáticamente.

Para ello necesitaríais:

  1. Crear un segundo modelo en Teachable Machine con una clase por cada miembro del grupo. Fotografiad cada cara desde al menos 20 ángulos distintos.
  2. Exportar ese segundo modelo y guardar su URL.
  3. En App Inventor, añadir un segundo componente ImageClassifier con la URL del modelo de caras.
  4. Añadir un botón "CAMBIAR A MODO ALUMNO" que detenga el clasificador de libros y active el de caras.
  5. Cuando el clasificador de caras reconozca a alguien, su nombre se rellena automáticamente en lugar de escribirlo.

Nota: esta ampliación requiere que los padres hayan firmado la autorización de uso de imagen. Si es vuestro caso, ¡adelante!

  2. En App Inventor: menú "Connect" → "AI Companion".
  3. Aparece un código QR. Escaneadlo con la app de la tablet.

Descargar MIT AI2 Companion
Guía de pruebas — comprobad todo esto
  1. Apuntad a cada uno de los 5 libros. ¿Aparece el título correcto en lblLibro?
  2. Con un libro reconocido, escribid un nombre y pulsad REGISTRAR PRÉSTAMO. ¿Aparece el mensaje con el nombre y la fecha?
  3. Cerrad la app y volved a abrirla. Apuntad al mismo libro. ¿Sigue apareciendo como prestado con el nombre y la fecha? (Si no, hay un error en el bloque Initialize.)
  4. Pulsad REGISTRAR DEVOLUCIÓN. ¿Vuelve a "Disponible"?
  5. Intentad reservar un libro ya prestado. ¿Aparece la alerta correcta?
  6. Pulsad RESERVAR sin haber escrito el nombre. ¿Aparece la alerta?
  7. Apuntad a algo que no sea ningún libro. ¿Qué muestra la app?
Errores frecuentes y cómo solucionarlos
  • La cámara no se activa: comprobad que StartContinuousClassification está en el bloque Initialize y que la URL del modelo es correcta en el componente ImageClassifier.
  • No reconoce bien un libro: volved a Teachable Machine, añadid más fotos con más variedad de ángulos y luz, exportad de nuevo y actualizad la URL en App Inventor.
  • El estado no se guarda al cerrar: comprobad que StoreValue y GetValue usan exactamente la misma clave. "estado_El Quijote" y "estado_el quijote" son claves distintas.
  • La fecha no aparece: verificad que el componente Clock está añadido en el Designer.
  • La alerta no aparece: comprobad que habéis añadido el componente Notifier en el Designer.
Documentad mientras probáis
  1. ¿Qué ha fallado? ¿Cómo lo habéis solucionado?
  2. ¿Hay algún libro que la app sigue sin reconocer bien? ¿Por qué creéis que ocurre?
  3. ¿Qué mejoraríais si tuvierais más tiempo?
06
Concluir

Presentamos y reflexionamos

El último paso es compartir lo que habéis construido y lo que habéis aprendido. No basta con que funcione: hay que saber explicar cómo y por qué.

Guía de la presentación — qué debe incluir
  • Demostración en directo: reconocéis un libro, escribís el nombre, registráis el préstamo, mostráis que persiste al cerrar y abrirla de nuevo, y registráis la devolución.
  • El proceso de entrenamiento: ¿cuántas fotos hicisteis? ¿Qué dificultades tuvisteis con el modelo?
  • Las decisiones de programación: ¿qué hace TinyDB? ¿Por qué comprobáis que hay nombre antes de registrar?
  • Limitaciones detectadas: ¿qué falla con mala luz? ¿Con portadas similares? ¿Qué pasaría con 200 libros?
  • Reflexión ética: ¿qué implicaciones tendría escalar este sistema a toda la biblioteca?
  • Escalabilidad: ¿qué habría que cambiar técnicamente para que funcionara con toda la biblioteca?
Reflexión individual final — cierra el círculo
  1. Antes de esta unidad, ¿cómo creías que aprendía una IA? ¿Ha cambiado esa idea?
  2. ¿Qué diferencia hay entre una IA que genera y una que clasifica? Explícalo con tus propias palabras.
  3. ¿Qué parte del proyecto te ha resultado más interesante? ¿Y más difícil?
  4. Si esta app se usara en una biblioteca real, ¿qué fallaría? ¿Qué habría que mejorar técnica y éticamente?
